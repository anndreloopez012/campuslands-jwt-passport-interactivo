DIAPOSITIVA 02 · INTRODUCCIÓN (RFC 7519)

¿Qué es un JSON Web Token (JWT)?

JSON Web Token (JWT) es un estándar abierto (RFC 7519) que define una forma compacta y autónoma de transmitir información de forma segura entre partes como un objeto JSON. Esta información se puede verificar y es confiable gracias a su firma digital. Los JWT se pueden firmar mediante un secreto compartido (con el algoritmo HMAC) o mediante un par de claves pública/privada usando RSA o ECDSA.

DIAPOSITIVA 03 · SEGURIDAD EN LOS JWT

Tokens Firmados vs. Tokens Cifrados

Aunque los JWT pueden cifrarse para proporcionar confidencialidad entre las partes, en APIs REST nos centramos en los tokens firmados (JWS). Los tokens firmados permiten verificar la integridad de las afirmaciones (claims) que contienen, mientras que los tokens cifrados las ocultan a otras partes. Cuando se firman con pares de claves pública/privada, la firma también certifica que solo quien posee la clave privada lo firmó.

DIAPOSITIVAS 04 Y 05 · VENTAJAS CLAVE

¿Por qué utilizar JWT en tus aplicaciones?

Las 6 razones fundamentales por las que JWT es el estándar de la industria en arquitecturas modernas:

✔ 1. Livianos y fáciles de usar

Su tamaño compacto en texto plano codificado los hace ideales para aplicaciones cliente como aplicaciones móviles y SPAs.

✔ 2. Autónomos (Stateless)

El servidor puede consumir el token directamente y utilizar una reclamación del token como identidad para ejecutar la solicitud sin consultar sesiones en memoria.

✔ 3. Firma Simétrica o Asimétrica

Pueden firmarse simétricamente con un secreto compartido mediante HMAC o asimétricamente mediante una clave privada (RSA / ECDSA).

✔ 4. Caducidad Incorporada

Tienen un mecanismo de expiración nativo (claim exp) que invalida el token automáticamente tras el tiempo definido.

✔ 5. Declaraciones Personalizadas

Se pueden ampliar libremente para que contengan declaraciones (custom claims) como roles, permisos o rango del usuario.

✔ 6. Adopción en SSO y Estándares

Son ampliamente adoptados por soluciones de inicio de sesión único (SSO) y estándares bien conocidos como OpenID Connect.

DIAPOSITIVA 06 · ESCENARIO #1

Autorización y Single Sign-On (SSO)

Es el escenario más común para el uso de JWT. Una vez que el usuario inicia sesión, cada solicitud posterior incluirá el JWT, permitiéndole acceder a rutas, servicios y recursos permitidos con ese token. El inicio de sesión único (SSO) utiliza ampliamente JWT debido a su bajo consumo de recursos y su facilidad de uso entre diferentes dominios.

DIAPOSITIVA 06 · ESCENARIO #2

Intercambio Seguro de Información

Los JSON Web Tokens son una excelente forma de transmitir información segura entre partes. Dado que se pueden firmar (por ejemplo, con pares de claves pública y privada), puedes estar seguro de que los remitentes son quienes dicen ser. Además, como la firma se calcula usando la cabecera y la carga útil, también verificas que el contenido no haya sido manipulado.

01 / ANATOMÍA DE UN JWT (SLIDES 7, 8 Y 9) · 5 MIN

Cabecera, Carga Útil y Firma

HEADER.PAYLOAD.SIG

Un JWT se compone de 3 partes codificadas en Base64Url separadas por un punto (.): Cabecera (Header), Carga útil (Payload) y Firma (Signature).

Header.Payload.Signature
1 Cabecera (Header)

Consta de dos partes: el tipo de token ("typ": "JWT") y el algoritmo de firma utilizado, como HMAC.SHA256 ("alg": "HS256") o RSASHA256. Se codifica en Base64Url para formar la primera parte del JWT.

2 Carga Útil (Payload)

Contiene las reclamaciones (claims): declaraciones sobre una entidad (el usuario) y datos adicionales. Existen tres tipos: registradas (sub, exp, iat), públicas (name) y privadas (admin: true).

3 Firma (Signature)

El encabezado codificado y la carga útil codificada se firman con el algoritmo del encabezado y el secreto: HMACSHA256(base64Url(header) + "." + base64Url(payload), secret). Garantiza que el mensaje no haya cambiado en el camino.

PASSPORT.JS
DIAPOSITIVA 10 · ¿QUÉ ES PASSPORT.JS?

Middleware Flexible, Modular y No Intrusivo

Passport.js es un middleware de autenticación flexible y modular para aplicaciones Node.js y Express que simplifica la verificación de la identidad de los usuarios. Su diseño es no intrusivo, lo que permite integrarlo fácilmente en cualquier aplicación web sin imponer estructuras de base de datos o rutas específicas, dejando esas decisiones al desarrollador. Su funcionalidad principal se basa en el uso de estrategias (plugins).

DIAPOSITIVA 12 · CARACTERÍSTICAS

Sesiones, Modo Stateless y Hooks Claros

Además de manejar la verificación, Passport puede gestionar la persistencia de sesiones mediante la serialización y deserialización de usuarios en cookies o almacenamiento de sesiones, o bien operar sin estado (session: false) con JWT. Proporciona hooks claros para controlar el éxito o fallo del proceso de autenticación.

1import jwt from "jsonwebtoken";
2import { CAZADORES_SEMILLA } from "../models/cazador.model.js";
3import { PerfilCazadorDTO } from "../dtos/cazador.dto.js";
4
5export const JWT_SECRET = process.env.JWT_SECRET || "campuslands_secret_key_256_bits";
6export const JWT_EXPIRES_IN = "2h";
7const recompensasMemoria = [];
8
9export const cazadorService = {
10  async buscarPorUsername(username) {
11    const limpio = String(username ?? "").trim().toLowerCase();
12    return CAZADORES_SEMILLA.find((c) => c.username === limpio) || null;
13  },
14  async buscarPorSub(sub) {
15    return CAZADORES_SEMILLA.find((c) => c.sub === String(sub)) || null;
16  },
17  async listarPerfiles() {
18    return CAZADORES_SEMILLA.map((c) => new PerfilCazadorDTO(c));
19  },
20  firmarTokenJWT(cazador) {
21    const payload = {
22      sub: cazador.sub, // Claim registrada: sujeto único
23      username: cazador.username,
24      name: cazador.name, // Claim pública
25      rango: cazador.rango, // Claim privada personalizada
26      admin: Boolean(cazador.admin), // Claim privada de autorización
27    };
28    return jwt.sign(payload, JWT_SECRET, { algorithm: "HS256", expiresIn: JWT_EXPIRES_IN });
29  },
30  async crearRecompensa(datos, adminUsername) {
31    const nueva = { id: `bov-${Date.now()}`, ...datos, autorizadoPor: adminUsername, createdAt: new Date().toISOString() };
32    recompensasMemoria.unshift(nueva);
33    return nueva;
34  },
35};

PASO 5

Crea api/src/config/passport.js registrando ambas estrategias en modo sin sesiones (session: false).

CREA · api/src/config/passport.js 
1import passport from "passport";
2import { Strategy as LocalStrategy } from "passport-local";
3import { Strategy as JwtStrategy, ExtractJwt } from "passport-jwt";
4import { cazadorService, JWT_SECRET } from "../services/cazador.service.js";
5import { PerfilCazadorDTO } from "../dtos/cazador.dto.js";
6
7export { JWT_SECRET };
8
9export function configurarPassport() {
10  // 1. Estrategia Local: valida credenciales en POST /users/authenticate
11  passport.use("local", new LocalStrategy(
12    { usernameField: "username", passwordField: "password", session: false },
13    async (username, password, done) => {
14      try {
15        const cazador = await cazadorService.buscarPorUsername(username);
16        if (!cazador || cazador.password !== password) {
17          return done(null, false, { message: "Credenciales inválidas: usuario o contraseña incorrectos" });
18        }
19        return done(null, cazador);
20      } catch (error) { return done(error); }
21    }
22  ));
23
24  // 2. Estrategia JWT: extrae Bearer Token, valida firma HS256 y expiración (exp)
25  passport.use("jwt", new JwtStrategy(
26    {
27      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
28      secretOrKey: JWT_SECRET,
29      algorithms: ["HS256"],
30    },
31    async (jwtPayload, done) => {
32      try {
33        const cazador = await cazadorService.buscarPorSub(jwtPayload.sub);
34        if (!cazador) return done(null, false, { message: "El titular del token no existe" });
35        return done(null, { ...new PerfilCazadorDTO(cazador), claims: jwtPayload });
36      } catch (error) { return done(error, false); }
37    }
38  ));
39
40  return passport;
41}

1import passport from "passport";
2import { CredencialesDTO } from "../dtos/cazador.dto.js";
3
4export function autenticarLocal(req, res, next) {
5  const dto = new CredencialesDTO(req.body);
6  req.body.username = dto.username;
7  req.body.password = dto.password;
8
9  passport.authenticate("local", { session: false }, (err, cazador, info) => {
10    if (err) return next(err);
11    if (!cazador) return res.status(401).json({ error: info?.message || "Credenciales inválidas" });
12    req.user = cazador;
13    next();
14  })(req, res, next);
15}
16
17export function autenticarJWT(req, res, next) {
18  const authHeader = req.headers.authorization;
19  if (!authHeader || !authHeader.startsWith("Bearer ")) {
20    return res.status(401).json({ error: "Acceso denegado: debes enviar el header Authorization: Bearer [JWT Token]" });
21  }
22
23  passport.authenticate("jwt", { session: false }, (err, usuarioVerificado, info) => {
24    if (err) return next(err);
25    if (!usuarioVerificado) {
26      return res.status(401).json({
27        error: "Token JWT inválido, firma alterada o expirado",
28        detalle: info?.message || "Fallo en la verificación criptográfica HMAC-SHA256",
29      });
30    }
31    req.user = usuarioVerificado;
32    next();
33  })(req, res, next);
34}
35
36export function autorizarAdmin(req, res, next) {
37  if (!req.user?.admin) {
38    return res.status(403).json({
39      error: "Prohibido (403): tu token es válido, pero necesitas reclamación admin: true para abrir la Bóveda Maestra",
40      rangoActual: req.user?.rango ?? "desconocido",
41    });
42  }
43  next();
44}
